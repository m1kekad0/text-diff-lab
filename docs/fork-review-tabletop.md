# 外部forkレビューの机上確認

2026-10-08、実行を伴わない合成3ケースです。エージェントが下表の判断を整理しました。Humanによる演習・workflow承認・実forkの安全確認を済ませた記録ではありません。

[既存の外部fork手順](contributing.md#外部forkからのprを確認するとき)を使い、Humanは各ケースで「何を読むか・実行をどう扱うか・なぜ」を先に答えてから下表と照合してください。実forkの取得・ローカル実行、外部PRの作成、workflow承認、security設定変更は行いません。

| 合成ケース | 期待する判断と理由 |
| --- | --- |
| READMEの誤字だけを直すPR。現在のHEADの全差分は本当に1行の文書変更のみ。 | 文面・リンク・公開可能性を読む。無害な文書差分としてレビュー継続可。実行承認が必要ならHumanがこのHEADの全差分を確認して判断する。文書という題名だけで承認しない。 |
| 「文書修正」というPRに `package.json` のtest command、`scripts/` またはworkflowの変更もある。 | 実行はHOLD。呼出先・追加依存・権限・送信先まで読む。既存CIでもPRのスクリプトを実行するため、workflowファイルが無変更でも危険を除外できない。判断できなければ承認せず、設定を緩めない。 |
| 不具合PRに実利用者の入力を含むログや画像が添付されている。 | 内容を転載・実行せずレビューを止める。最小の合成例への置換を求める対応と、既公開情報の除去が必要かをHumanが判断する。ブラウザ内処理でもGitHub添付は別の公開であり、アプリのprivacy説明では保護できない。 |

HEADが変わったら全差分を読み直します。CIのgreenや以前の承認は、変更後のコードを実行してよい根拠にはなりません。PR #4ではHumanがReadyにした後も失敗CIによるmerge blockを観測しましたが、これはforkコードの安全性やworkflow承認の演習とは別です。

この演習の完了条件はHumanが3つの理由を説明できることです。実際の承認・Ready・merge・Releaseは各対象の最新証拠を確認してHumanが判断します。
